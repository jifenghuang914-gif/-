# UK 红包策略机器学习测算口径

## 1. 数据输入

常见输入包括：

- 新/旧策略表：生命周期、来源、分类、旧权益、新权益、红包ID、任务ID。
- 红包领取表：统计日期、国家/城市、红包id、红包面额、红包门槛金额、领取红包数。
- 红包核销表：国家/城市、红包id、红包面额、红包门槛金额、核销张数、订单收入、红包平台补贴、CM3/订单CM3、GMV、rev。
- 核心指标表：APP活跃人数、GMV、平台C补、订单数等，用于 DAU 或大盘 GMV 分母。

读取时先判断源表是逐日、周总还是长周期汇总。用户明确指定日期窗口时，以用户口径优先。

## 2. 权益解析

将文本权益解析为标准字段：

- `满减券：30-7` 表示门槛 `30`、面额 `7`。
- `无门槛：cap5` 表示无门槛券，补贴按 cap/券面额计算；做力度比较时可按门槛 `5` 处理。
- `会员可用`、`会员`、`带（会员）` 等按用户口径识别会员专属；没有写会员时默认非会员。
- 来源名称包含会员红包发放、会员专属等，也按会员专属处理。

结构化键建议至少包含：`面额`、`门槛`。当用户要求更细时，再加入来源、生命周期、会员属性、频次、客单/笔单标签。

## 3. 历史命中与回退

优先级：

1. 新权益组合在历史长周期中直接命中：使用该组合合计核销率和单均表现。
2. 新权益未命中，但旧权益组合命中：使用旧权益组合表现，并按新旧力度变化修正核销率。
3. 旧权益也未命中：使用相近面额/门槛、同来源、同会员属性、同人群标签样本；标记低置信。
4. 没有可用样本：留空或按用户指定兜底，不要悄悄填 0。

核销率必须用 `合计核销张数 / 合计领取红包数`，不要平均行级核销率。

常用力度修正规则：

- 新权益补贴力度高于旧权益：核销率上调，默认不超过 `+0.5pp`。
- 新权益补贴力度低于旧权益：核销率下调，默认不超过 `-0.5pp`。
- 新旧力度相同：不调整。

如果用户要求“直接按照命中的历史核销率”，命中项不得再额外浮动。

## 4. 预测公式

周总口径：

| 字段 | 公式 |
| --- | --- |
| 领取数 | 按旧红包ID或用户指定ID锁定的窗口领取数周总 |
| 预估核销率 | 新权益命中历史核销率；未命中按回退规则 |
| 预估订单量 | 领取数 × 预估核销率 |
| 预估总补贴 | 预估订单量 × 新权益面额/cap |
| 预估总CM3 | 预估订单量 × 预估单均CM3 |
| 预估总REV | 预估订单量 × 预估单均REV |
| 预估实付金额 | 预估订单量 × 预估实付笔单价 |
| 预估GMV | 预估订单量 × 预估交易笔单价 |

日均口径：

- 行级如果要求日均，则周总除以日期天数。
- 底部增量表若要求日均，则先算周总新旧差值，再统一除以日期天数，或让每个总量行除以日期天数后相减；两者必须一致。

## 5. 老策略历史

老策略历史按旧红包 ID 锁定，不按新权益组合回推。窗口为用户指定日期，例如 `0809-0815` 时：

- 领取数：领取表按旧红包 ID 聚合 0809-0815 周总。
- 核销率：核销张数 / 领取红包数。
- 订单数、实付总额、订单CM3、红包平台补贴、GMV、rev：核销表按旧红包 ID 聚合周总。
- 如果右侧历史表头要求周总，就不除以 7；如果要求日均，就除以 7。

## 6. C补rate 分母

必须按表格语义区分：

- 大盘或底部策略增量表中的 `C补rate`：通常用 `C端补贴 / 大盘GMV`，大盘 GMV 来自核心指标表或表中指定单元格。
- 红包行级或工具自身效率中的 `C补rate`：通常用 `红包平台补贴 / 红包GMV`。

当用户明确纠正分母时，以用户说法为准，并在表格备注或交付说明中写清。

## 7. 输出布局建议

预测区常见顺序：

`领取数`、`预估核销率`、`预估订单量`、`预估总补贴`、`预估单均cm3`、`预估实付笔单价`、`预估交易笔单价`、`预估单均REV`、`预估总CM3`、`预估总REV`

右侧历史区常见顺序：

`核销率`、`订单数`、`实付总额`、`订单CM3`、`红包平台补贴`、`GMV`、`C补rate`、`rev`

底部变化表常见字段：

`订单量`、`C端补贴`、`实付金额`、`CM3`、`GMV`、`C补rate`、`REV`

## 8. QA 清单

- 检查目标红包 ID 是否全部在领取表和核销表命中；未命中要列出。
- 检查新权益组合历史命中数量、旧权益回退数量、低置信数量。
- 抽查无门槛 cap 券补贴是否按 cap/面额计算，不能填 0。
- 抽查周总和日均是否混用，尤其行级和底部汇总。
- 扫描公式错误：`#REF!/#DIV/0!/#VALUE!/#NAME?/#N/A`。
- 渲染或读取关键区域，确认新增列没有覆盖历史区，表头和数值可读。
