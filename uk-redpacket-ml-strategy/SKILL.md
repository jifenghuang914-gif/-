# UK 红包策略机器学习式测算

用于用户要求“根据历史红包数据预测新红包力度组合”“测算 UK 新生命周期/天降/任务中心红包策略调整”“按权益组合命中历史核销率”或类似红包策略机器学习测算时。普通周报填充、只按既有模板补数的任务优先使用 `$策略复盘填充`；本技能关注预测、测算和新旧策略模拟。

## 核心思路

把红包文本和源表字段统一拆成结构化权益组合：`红包面额`、`红包门槛金额`、`补贴力度=面额/门槛`、是否无门槛、会员属性、来源、生命周期、频次、客单/笔单标签。预测新策略时，优先使用历史中相同权益组合的真实表现；没有直接命中时，再使用旧权益或相近权益，并按力度提高/降低做小幅修正。所有单均、rate、核销率必须用合计分子/分母重算，不平均行级比例。

## 默认工作流

1. 先读取用户指定目录中的策略表、红包领取表、红包核销表、补贴效率表和核心指标表，识别日期窗口、周总/日均口径、红包 ID 字段和权益字段。
2. 解析策略表中的旧权益、新权益、红包 ID、生命周期、来源、会员/非会员、频次和客单标签。红包 ID、任务 ID 一律按文本处理，去掉 `.0`。
3. 构建历史训练/命中样本：
   - 领取表按 `红包id + 权益组合` 汇总领取数。
   - 核销表按 `红包id + 权益组合` 汇总核销张数、订单收入、红包平台补贴、订单CM3、GMV、rev。
   - 权益组合命中优先级通常为：新权益组合历史直接命中 > 旧权益组合历史 + 力度修正 > 相近权益组合 > 明确标记低置信。
4. 预测字段：
   - `预估核销率 = 命中历史核销率`；若新权益未命中，按旧/相近权益核销率结合力度变化小幅修正，常用上下浮动不超过 `0.5pp`，除非用户指定其他幅度。
   - `预估订单量 = 领取数 × 预估核销率`。
   - `预估总补贴 = 新权益面额 × 预估订单量`，无门槛 cap 券按 cap/券面额补贴，不能写 0。
   - `预估总CM3 = 预估订单量 × 预估单均CM3`。
   - `预估总REV = 预估订单量 × 预估单均REV`。
   - `预估实付金额 = 预估订单量 × 预估实付笔单价`。
   - `预估GMV = 预估订单量 × 预估交易笔单价`。
5. 输出新旧策略对比工作簿，不覆盖源文件。保留用户原样式；新增字段优先接在预测区后面，历史区放在右侧。

## 关键口径

需要详细测算时，读取 [references/calculation-caliber.md](references/calculation-caliber.md)。尤其注意：

- 用户要求周总时，行级领取数、订单数、补贴、GMV、CM3、REV 均用周总；底部增量表若要求日均，再统一除以天数。
- 老策略历史必须按旧红包 ID 锁定，不要用新权益反推旧历史。
- 大盘口径 `C补rate` 使用 `C端补贴 / 大盘GMV`；红包工具行级 `C补rate` 可使用该红包/工具 GMV，按用户表头语义区分。
- 会员可用按用户口径可视为会员专属券；没有写会员时默认非会员。来源包含会员红包发放时通常按会员专属处理。
- 天降、任务中心、犹豫时机等新生命周期策略才强匹配生命周期；其他来源不一定按生命周期匹配，除非用户明确要求。

## 输出与 QA

- 输出到源数据目录或用户指定目录，文件名带清晰后缀，例如 `_75天命中核销率`、`_含预估总CM3REV`、`_周总口径`。
- 公式优先保留在测算表中，关键汇总行写可追溯公式；同时写入缓存值便于预览。
- 完成前扫描 `#REF!/#DIV/0!/#VALUE!/#NAME?/#N/A`，抽查权益解析、ID 命中、周总/日均换算、C补rate 分母和无门槛补贴。
- 交付时说明命中情况，例如“30 行中 29 行直接命中 75 天新权益历史，1 行回退到旧权益力度修正”。
